# v2.0.0 — Configurable SvelteKit starter

Version 2.0 turns the minimal starter into a configurable SvelteKit 3 / Svelte 5 template with shared navigation and content blocks, switchable themes, a contact form, optional error monitoring, and automated validation from unit tests through production browser checks.

## Highlights

- Five Skeleton style presets with a persistent theme selector. Build configuration includes only selected palettes, example content and used blocks; optional primitives use direct imports.
- Responsive navigation with desktop dropdowns, a mobile menu, active links, Escape handling and focus restoration. Generic hero, plan and FAQ blocks share content-derived section navigation.
- Reusable contact form with subject prefill, validation, honeypot, pending/success/retry states and a Netlify Forms delivery adapter. An explicit Netlify adapter, deployment configuration and static form blueprint are included.
- Structured, sanitized logging and optional Sentry exception reporting. Without a DSN, Sentry is excluded from production chunks. Analytics, replay and performance tracing are not enabled.
- Unit/component coverage gates, desktop/mobile Playwright tests, Pa11y and rendered-contrast checks across presets, build-size/exclusion guards, and minimal/Sentry-enabled build checks.
- GitHub Actions validation with retained failure evidence, an agent CI diagnosis and repair runbook, grouped Dependabot updates and explicitly opt-in auto-merge with tested-commit gates.
- Coordinated framework and tooling upgrades, including remediation of the original moderate, high and critical dependency findings.

## Breaking changes and migration

- Use Node.js 22.17 or newer; CI and Netlify use Node 24. Install the committed dependency tree with `npm ci`.
- This starter now uses SvelteKit 3, Svelte 5, Vite 8, Vitest 4 and TypeScript 6. Skeleton remains on version 2. Existing consumers need to review their application code and integrations when adopting this major release.
- SvelteKit configuration is in `vite.config.ts`. Shared source imports use `#lib/*`; review older `$lib` imports and `svelte.config.js` configuration when migrating.
- The default deployment adapter is Netlify. Other hosts require a matching adapter and replacement contact delivery integration.
- Edit `template.config.mjs` to select branding, presets and example content. Rebuild after changing selections or the optional `PUBLIC_SENTRY_DSN`.
- Contact delivery is disabled until configured. Enable Netlify form detection, set private Function environment variables and configure notifications before relying on the form. The form requires JavaScript.

## Validation and limitations

Local validation of the v2.0.0 release candidate on November 10, 2026 passed a clean lockfile installation, the full release suite and the optional build matrix: 81 passing unit tests, 8 passing desktop/mobile browser tests and 200 accessibility audits with zero blocking Pa11y, contrast or runtime errors and no skipped source controls. Statement coverage was 97.62%, branch coverage 87.79%. Minimal, Sentry-enabled and restored default builds passed, including generated Netlify handler checks. Accessibility warnings remain available for manual review; automated checks do not replace assistive-technology testing.

The release candidate dependency audit retained five low-severity findings overall and four with development dependencies omitted, all inherited from the unpatched `deepmerge` chain. No moderate, high or critical findings remained. Audit results are time-sensitive; rerun both audits for the release revision.

Remote validation must pass for the exact release commit before publishing. Local checks do not prove live Netlify form detection, email notifications, Sentry delivery or remote auto-merge operation. No deployment or repository auto-merge opt-in is performed by this release.
